At the start of summer I teased the idea of using my GPU-equipped personal computer as a remote server that I could train models on. Having set up some basic forecasting last week, with how long it took to train the GPT forecasting on my puny laptop (which does not have a GPU), it seemed necessary to host an SSH server using WSL and NixOS.

My home computer natively runs windows, so I used [Windows Subsystem for Linux (WSL)](https://github.com/microsoft/WSL) to get a [NixOS](https://nixos.org/) instance running. NixOS is a fully declarative Linux distrubition that I've been daily driving for almost a year. Using my existing config, I was able to pretty quickly set up a barebones development environment. The beauty of WSL is that my Linux server is dynamically sharing resources with my Windows computer (like if Alex wants to play video games while I'm at Harvard), which is much more flexible than a VM. I also have it configured so that my server is launched whenver my desktop boots up. I then set up a [Secure Shell Protocol (SSH)](https://en.wikipedia.org/wiki/Secure_Shell) server to expose a command line interface, using [tailscale](https://tailscale.com/) to establish a connection between my laptop and my computer (rather than port forwarding). This enables me to connect to my SSH server from anywhere with an internet connection.

While NixOS's declarative nature makes it incredibly easy to reproduce my system on different machines, it isn't FHS compliant. This means that programs on NixOS aren't stored where they are in Linux distros (ie. in /etc or /bin) which is a big problem for Python development since packages often rely on various C dependencies. Originally my python development environment was centered around using [Nix flakes](https://wiki.nixos.org/wiki/Flakes), but after much struggling to get FHS compliancy, I switched to [nix-ld](https://github.com/nix-community/nix-ld) and [uv](https://docs.astral.sh/uv/). Simply put, nix-ld spoofs FHS compliance and uv is just a replacement for pip that I can easily configure through NixOS. In order to install the specific version of pytorch that's compatible with my 9 year old GPU, I also switched from a requirements.txt to a pyproject.toml. Anyone not using NixOS should still easily be able to replicate my development environment.

Without SSHing into my desktop, one epoch of forecasting training took around 15 minutes. On the SSH server, it takes around 90 seconds. Pretty big improvement!

The only blocker is that I messed up the configuration of my laptop while setting up the SSH server. Long story short, a core component of my computer, the Hyprland window manager, recently migrated their configuration format from their proprietary hyprlang language to Lua. In setting up my server, I updated all my packages, including Hyprland, so now I need to recongifure that and some other packages. Setting up the SSH server surprisingly didn't take too long, but reconfiguring is a huge hassle.

With faster training times, I saw that more training iterations slightly improved the forecasting results, but more fine tuning is still necessary. The predictions right now are pretty innacurate despite tuning some parameters.
